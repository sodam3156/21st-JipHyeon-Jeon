# 아이디어 포트폴리오

`D-010`(2026-07-25, accepted)에서 제품 책임자가 `IDEA-002 돌봄 집현전`을 메인 아이디어로 확정했습니다. Gate 3 정식 조건(Portfolio 진입 8개, 독립 반론)은 `governance.gate-log`에 `waived`(만료 2026-08-11)로 기록돼 있으며, seed가 존재한다는 사실만으로 기회·문제·고객이 검증된 것은 아닙니다.

## Seed 기록 조건

떠오른 아이디어를 잃지 않기 위해 이름, 한 문장, 연결을 시도할 기회 ID, 가장 큰 근거 공백만 있으면 `seed`로 기록할 수 있습니다. seed는 점수 비교·솔루션 구체화·P0 개발 대상이 아닙니다.

## Portfolio 진입 조건

`explore`로 승격해 포트폴리오에서 비교하려면 아래 조건을 모두 충족해야 합니다.

1. 연결된 기회 ID 1개
2. 개별 Gate 1이 `passed` 또는 `waived`인 서로 다른 인사이트 3개 이상
3. 구체 고객·촉발 상황·실패 행동·측정 가능한 손실
4. 현재 대안과 미충족 이유
5. AI가 바꾸는 판단 또는 남기는 업무 결과물
6. 최소 데이터와 결측·오류 처리
7. 3분 발표 안의 90초 핵심 데모에 들어갈 입력·상태 변화·최종 결과물
8. 48시간 안에 반박할 수 있는 치명 가정

## 상태

- `seed`: 아이디어를 잃지 않기 위한 초기 메모; Gate 3 미진입
- `explore`: Portfolio 진입 조건 8개와 Gate 3를 통과한 비교 후보
- `validated`: 문제·데이터·데모 가정이 최소 기준을 통과
- `selected`: 제품 책임자가 결정 로그로 선택
- `rejected`: 근거 또는 실행 조건 때문에 폐기
- `parked`: 현재 기간에는 보류

### IDEA-001 — 회동(會同)

- 문제 가설: HYP-001
- 선택 결정: 없음 (D-010으로 IDEA-002가 선택되며 `parked`; 폐기 아님, 재검토 가능)

역사적 아이디어 문장:

> 무차량 고려대 세종캠퍼스 학생이 4–8명 문화·취미 모임의 시간·예산·취향·이동 조건을 조율해 실행 가능한 일정안으로 합의하도록 돕는다.

판정:

- 검증 대상이 구체적이고 집현전 표현과 연결하기 쉽습니다.
- SJ-P-0022–0024의 문화 수요 문제와 접점은 있으나, “문화 콘텐츠 부족·발견 실패”와 “친구 모임 조율 실패”는 같은 문제로 간주할 수 없습니다.
- 기존 솔루션 문서는 이 후보를 먼저 구체화했던 **보관 기록**이며 현재 설계 기준이 아닙니다.
- 최근 실제 모임 조율 실패 5건과 기존 도구의 미충족 지점, Gate 3의 나머지 조건이 확인되기 전 `explore`로 올리지 않습니다.

### IDEA-002 — 돌봄 집현전

- 문제 가설: 세종의 6–36개월 자녀 보호자가 갑작스러운 평일 2–4시간 돌봄 공백에서 공식 시간제보육의 조건과 신청 경로를 제때 연결하지 못한다.
- 해결 원리: 자연어 조건을 구조화하고 공식 규칙·출처·안전 경계를 독립 검증해 `돌봄 확보 실행카드`를 만든다.
- 선택 결정: D-010 (accepted, 2026-07-25)
- 현재 상태: `selected`; Portfolio 진입조건 8개와 Gate 3 정식 판정은 `governance.gate-log`에 waived(만료 2026-08-11)로 기록. `X-006`과 이슈 #3·#4 결과로 사후 확인 예정

제안 산출물:

- 조건 일치·불일치·미확인
- 공식 후보의 연락 순서
- 준비 체크리스트와 전화 질문
- 공식 신청 링크·전화번호
- 출처와 확인일
- 실제 예약 가능 여부를 기관에 확인하라는 인계
- 해결 불가 시 공식 상담창구와 대체 경로

AI는 입력 구조화와 설명을 맡고, 규칙은 공개 자격·시간을 판정하며, 보호자는 우선순위와 신청을 결정하고, 기관은 실제 자격·가용성·예약을 승인합니다.

## 공통 비교표

Gate 3를 통과한 후보만 같은 근거량과 조건에서 아래 척도로 평가합니다.

- `unsupported`: 근거 없음 또는 치명적 불일치
- `weak`: 내부 추정이나 약한 2차 근거만 있음
- `supported`: 복수 근거 또는 초기 행동 증거가 있음
- `strong`: 직접 행동·테스트·접근 가능한 데이터로 확인

| 평가축 | 통과 질문 |
|---|---|
| 문제 증거 | 최근 행동, 빈도, 손실, 대안 실패가 확인됐는가? |
| 고객 접근성 | 48시간 안에 고객과 도메인 판정자를 만날 수 있는가? |
| 세종·대주제 적합성 | 세종 요소와 AI 콘텐츠 제작이 결과를 실제로 바꾸는가? |
| AI 필요성 | 규칙·검색만으로 충분하지 않고 판단·생성·조정 가치가 있는가? |
| 데모 상태 변화 | 3분 발표 안의 90초 핵심 데모에서 전후 차이와 결과물이 보이는가? |
| 데이터·기술 가능성 | 최소 데이터, 계약, 오류·결측 경로가 확보되는가? |
| 위험·운영 경계 | 사람 승인, 개인정보, 안전, 비용 경계가 있는가? |
| 차별성·재사용 | 남은 병목과 두 번째 사용 사건이 있는가? |

등급을 숫자로 환산하거나 총점으로 자동 선택하지 않습니다. 아래 탈락 조건에 해당하면 다른 축의 평가와 무관하게 선택하지 않습니다.

## 즉시 탈락 조건

- 고객 또는 상황이 둘 이상 핵심 집단으로 갈라짐
- 실제 공급 부족을 앱이 해결한다고 주장함
- 핵심 데이터의 접근·권리·최신성을 확인할 수 없음
- AI 출력이 근거 없는 추천 문장에 그침
- 고위험 행동을 사람 승인 없이 실행함
- 데모의 핵심 상태 변화가 실제로 구현되지 않음
- 48시간 반증 실험을 정의할 수 없음
- 세종 요소를 제거해도 결과가 동일함

## 선택 절차

1. `AR-003`에서 실제 행동을 검증할 기회 영역 두 개를 고릅니다.
2. 두 영역이 Gate 2를 통과하면 영역마다 AI가 최대 두 개 아이디어만 제안합니다.
3. 독립적인 반론 에이전트가 최대 네 후보의 근거 사슬과 탈락 조건을 검사해 비교 후보를 최대 세 개로 줄입니다.
4. 남은 후보마다 `planning.solution-portfolio`에 같은 깊이의 최소 솔루션 카드를 만들고 Gate 4를 판정합니다.
5. 남은 후보는 같은 입력·시간·데이터 조건으로 비교합니다.
6. 치명 가정을 실제 인터뷰 또는 프로토타입으로 검증합니다.
7. AI 평가자는 축별 근거 등급, 추천, 불확실성만 기록합니다.
8. 제품 책임자가 `governance.decision-log`에 선택·보류·폐기 결정을 남깁니다.
