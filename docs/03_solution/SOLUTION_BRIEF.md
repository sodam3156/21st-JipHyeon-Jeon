# 솔루션 개요 — 돌봄 집현전 (SOL-002)

> `D-010`(2026-07-25, accepted)으로 선택됐습니다. Gate 4 정식 조건은 `governance.gate-log`에 `waived`(만료 2026-08-11)로 기록돼 있으며, 이슈 #4 결과로 확인 필드를 확정할 때까지 아래 계약은 잠정입니다. IDEA-001/SOL-001의 이전 기록은 Git 이력으로만 보존됩니다.

## 연결

`SOL-002` · `IDEA-002` · `OPP-005` · `IN-001·006·007·009·017–019` · `E-004·007·008` · `X-006`

## 구체 고객과 대표 사건

세종 거주, 6–36개월 자녀를 가정양육하는 보호자가 갑작스러운 평일 2–4시간 돌봄 공백을 겪는 사건.

## 이전 상태 → 목표 상태

- 이전 상태: 공식 조건·신청 경로·확인할 항목이 흩어져 다음 행동을 정하지 못함
- 목표 상태: 5분 안에 공식 다음 행동과 미확인 항목을 구분하고 신청·전화로 인계

## 이벤트 → 판단 → 도구 → 결과물 → 다음 행동

1. 이벤트: 보호자가 생활권·연령구간·날짜·시간·긴급성·이동수단·아이사랑 등록 준비 여부를 입력
2. 판단: 자격·정책 검증, 기관·최신성 검증, 안전·금지행동 감사
3. 도구: 공식 원천(중앙/세종육아종합지원센터 시간제보육, 아이사랑, 공공데이터포털 어린이집 API) 조회
4. 결과물: `돌봄 확보 실행카드` — 조건 일치/불일치/미확인, 공식 후보 연락 순서, 준비 체크리스트·전화 스크립트, 공식 링크·전화, 출처·확인일
5. 다음 행동: 보호자가 우선순위를 수정한 뒤 공식 신청 또는 기관 전화

## P0 · P1 · 제외 범위

- P0: 6–36개월 / 평일 / 2–4시간 / 공식 시간제보육 조건 판정과 인계
- 제외(명시적 금지): 실시간 잔여석·예약 성공 주장, 시설 안전성·품질 순위, 비공식 돌보미 매칭, 의료·아동안전 판단, 아동 이름·정확한 생년월일·상세주소·건강정보 수집·저장, 공식기관 검토 전 "공식 연계 서비스" 표현

## 입력·출력·데이터 출처·시점·결측 계약

- 입력: 생활권(대략), 연령구간, 희망 날짜·시간, 긴급성, 이동수단, 아이사랑 등록 준비 여부
- 출력: 실행카드(위 결과물 항목), 모든 값에 공식 URL과 확인일 표기
- 데이터 출처: 이슈 #4에서 확인할 공식 원천 4종
- 결측 처리: 확인 불가한 값은 `확인 불가`로 표기하고 공식 확인 경로로 인계, 실시간 API 미승인 시 공식 deep-link + 전화 인계 + 확인일 표시된 검증 fixture로 축소

## AI·규칙·사람의 책임과 승인 경계

- AI: 자연어 입력 구조화와 설명
- 규칙: 공개 자격·시간 조건 판정
- 보호자: 우선순위·신청 결정
- 기관: 실제 자격·가용성·예약 승인
- 사람 검토(이슈 #5 승인 팀 기준): 기획QA(최근 행동·문구·QA), 백엔드보안(최소수집·무저장 세션·공식 원천·fallback), 프론트UX(불확실성·인계·접근성), 비주얼디자인(캐릭터 권위자 오인·긴급상황 희화화 방지), 팀장PM(범위·비교군 교체·후보 승격)

## 오류·장애 축소 모드

timeout·429·형식 오류·오래된 데이터·API 장애 시: 확인일을 표시한 검증 fixture와 공식 deep-link만 사용하는 오프라인 축소 모드로 전환. 근거가 다르거나 오래됐으면 결과를 확정하지 않고 `확인 불가`와 공식 확인 경로를 제시.

## 3분 발표 안의 90초 핵심 데모

입력(조건) → 판단(자격·정책·최신성) → 실행카드 출력 → 인계(신청/전화)의 상태 변화를 보여준다. 이슈 #4 결과가 반영된 실제 공식 링크·확인일을 사용한다.

## 수용 기준

- 조건 일치/불일치/미확인 판정이 5분 안에 나온다
- 모든 값에 공식 URL과 확인일이 있다
- 실시간 잔여석·예약 성공을 주장하지 않는다
- 로그에 아동 식별정보·상세주소·건강정보가 남지 않는다

## 치명 가정·반증 실험·남은 위험

- 치명 가정: 보호자가 공급 부재가 아니라 조건·절차 분산 때문에 반복 검색·전화와 일정 손실을 겪는가 (이슈 #3 검증)
- 반증 실험: `X-006`, 이슈 #3(48시간 검증)·#4(공식 데이터 스파이크)
- 남은 위험: 실제 공급 부재가 핵심 원인일 위험, 공식 원천 API 미승인 시 P0 축소 필요, 개인정보 없이 가치 제공이 불가능할 위험
