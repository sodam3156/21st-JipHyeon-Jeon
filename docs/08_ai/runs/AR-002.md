# AR-002 — 인사이트 합성·반론 감사

## 작업 봉투

- 단계: insight
- 질문: 제공 원천의 중복을 제거하면 어떤 설계 제약이 남는가?
- 입력: AR-001, E-004–006, HYP-001, SJ-P-0001–0029
- 금지: 특정 아이디어에 유리한 사후 논리, 기술 자료로 고객 고통 증명, 메인 아이디어 선택

## 독립 관점

- 해커톤 전략: 120개 항목의 지속 제약과 반복·조건부 주장을 분리
- 세종 문제: 29개 문제의 원형·고객 구체성·근거·AI 적합성·데이터 위험을 분리
- 기술 조사: 329개 영상 항목에서 계약·검증·권한·예산·복구 원칙만 추출
- 통합 반론: 원천 용도 혼합, 조사 편향, 거짓 정밀성, 회동 가설의 근거 공백을 검사

## 결과

- 인사이트 정본: `planning.insight-ledger`
- 등록 인사이트: IN-001–020 (`active`와 고객 검증 전 `qualified`를 구분)
- 기회 영역 정본: `planning.opportunity-map`
- 핵심 결론:
  - 대표 사건 하나와 검증 가능한 상태 변화가 필요합니다.
  - 세종 특화는 데이터·생활권·업무 구조가 결과를 바꾸는 것입니다.
  - 문제은행의 반복 원형은 마감시각이 있는 조정 실패입니다.
  - 기술 자료는 고객 근거가 아니라 계약·권한·실패 복구에만 사용합니다.
  - IDEA-001은 고객 접근성은 높지만 최근 행동 근거가 없습니다.

## 검증

- 의미 중복을 20개 설계 제약으로 통합
- 인사이트마다 근거·선택 영향·예방 실패·신뢰도 기록
- 검색 편향과 적용하지 말아야 할 주장 기록
- OPP-001–003을 최종 선택이 아닌 다음 비교군으로 제한
