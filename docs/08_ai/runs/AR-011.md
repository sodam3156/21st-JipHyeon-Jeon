# AR-011 — 돌봄 인사이트 challenger 설계

## 실행 질문

사용자가 주입한 “세종에서 돌봄시설을 찾기 어렵고 시간제 돌봄 신청·선택을 연결할 필요가 있다”는 인사이트를 어떤 최소 고객·사건·솔루션·반증 실험으로 바꿀 것인가?

## 독립 역할

- Insight Synthesizer: 고객·상황·문제와 근거·가설 분리
- Solution Architect: 세 가지 해결 원리와 P0·계약·실패 경로
- Red Team: 기존 공식 서비스, 공급 부족, 안전·책임·최신성 반론

세 역할은 같은 결론을 합의하도록 강제하지 않았습니다. Red Team이 즉시 승격을 반대했으므로 OPP-005의 `parked` 상태를 유지했습니다.

## 근거와 가설

확인한 것은 다음입니다.

- 멘토 1인의 돌봄시설·센터 탐색 경험은 탐색 방향을 만드는 단서입니다.
- 문제은행에는 맞벌이 돌봄 공백, 시설 공급 부족, 개원 정보 지연 사례가 있습니다.
- 공식 시간제보육은 연령·운영시간·예약·등록 조건과 공식 신청 경로를 이미 제공합니다.
- 공공 어린이집 정보 API는 시설 기본정보를 제공하지만 실시간 빈자리·예약 성공은 확인되지 않았습니다.

아직 가설인 것은 다음입니다.

- 보호자의 핵심 병목이 공급 부재보다 조건·절차 분산입니다.
- 최근 3개월 안에 같은 실패가 반복됐습니다.
- 실행카드가 실시간 빈자리 없이도 기존 공식 웹보다 완료시간과 오접수를 줄입니다.
- 운영자가 반복 오문의 유형과 갱신 가능한 필드를 제공합니다.

## 제안 고객·사건

세종에 거주하며 6–36개월 자녀를 가정양육하는 보호자가 갑작스러운 평일 2–4시간 돌봄 공백을 겪고, 진료·근무·필수 일정 전까지 공식 시간제보육의 조건을 확인해 신청 또는 전화라는 다음 행동을 정해야 하는 사건입니다.

## 비교한 해결 원리

1. 공식 시간제보육 실행 라우터: 조건 판정과 공식 다음 행동을 실행카드로 만듦
2. 주간 돌봄 공백 캘린더: 공백을 미리 탐지하지만 입력 부담과 갑작스러운 사건 누락
3. 익명 수요 증거판: 기관 공급 결정에 도움을 줄 수 있으나 양면 도입과 즉시 사용자 가치가 약함

검증 후보는 1번입니다. 이는 선정 결정이 아니라 가장 먼저 반증할 최소 해결 원리입니다.

## P0 계약

입력:

- 대략 생활권
- 연령구간
- 희망 날짜·시간
- 긴급성
- 이동수단
- 아이사랑 등록 준비 여부

검증 역할:

- 자격·정책 검증
- 기관·운영정보 최신성 검증
- 안전·금지행동 감사
- 근거 충돌 시 중단하는 조정자

출력 `돌봄 확보 실행카드`:

- 조건 일치·불일치·미확인
- 공식 후보의 연락 순서
- 준비 체크리스트와 전화 질문
- 공식 신청 링크·전화
- 출처와 확인일
- 예약 가능 여부 직접 확인 안내
- 해결 불가 시 공식 상담창구와 대체 경로

## 즉시 탈락 조건

1. 기관 연동 없이 실시간 빈자리·예약 성공 주장
2. 불완전 공시정보로 시설 안전성·품질 순위 제공
3. 비공식 돌보미 매칭 또는 의료·아동안전 판단
4. 출처·기준일·불확실성 없는 확정 답변
5. 아동 이름·정확한 생년월일·상세주소·건강정보 수집·저장
6. 합성 데이터를 실제 세종 가용 현황처럼 시연
7. 기존 공식 서비스가 없다고 발표
8. 모든 부모·연령·돌봄 유형을 한 P0에 포함
9. 캐릭터만 다른 에이전트로 멀티에이전트 필요성을 주장
10. 보호자·운영자 검증 없이 메인 후보로 승격

## 48시간 X-006

- 보호자 6명 중 4명 이상이 최근 3개월 내 실제 사건을 재구성합니다.
- 3명 이상이 두 경로 이상을 거치고 같은 정보 때문에 마감 전 결정을 못 했습니다.
- 3명 이상이 30분 이상 탐색·일정 지연·취소·미해결 중 하나를 제시합니다.
- 운영자 2명 중 1명 이상이 반복 오문과 갱신 가능한 공식 필드를 확인합니다.
- 시안 6명 중 4명 이상이 5분 안에 공식 다음 행동과 미확인을 구분합니다.
- 잘못된 경로·자리 보장·비공식 매칭·의료 판단·민감정보 노출은 0건입니다.
- 보호자 4명 이상에게 핵심 원인이 실제 공급 부재라면 실패합니다.

실행은 [Issue #3](https://github.com/sodam3156/21st-JipHyeon-Jeon/issues/3), 공식 데이터·신청 경로는 [Issue #4](https://github.com/sodam3156/21st-JipHyeon-Jeon/issues/4), 결정은 [Issue #5](https://github.com/sodam3156/21st-JipHyeon-Jeon/issues/5)에서 관리합니다.
