# 검증 근거

이 문서는 고객·문제·솔루션 가설을 지지하거나 반박하는 근거의 정본입니다. 조사 원천의 목록과 용도는 `validation.research-source-catalog`, 그 원천에서 합성한 설계 제약은 `planning.insight-ledger`에 기록합니다.

숫자나 인용을 만들지 않으며, 한 사람의 의견을 시장 전체의 사실로 일반화하지 않습니다.

## 근거 기술 방식

하나의 A–E 등급으로 강도를 표현하지 않습니다. 근거마다 다음을 분리합니다.

- 유형: 행동 관찰, 인터뷰, 공식 원문·데이터, 전문가·2차 자료, 미검증 가설, 누적 편집물
- 대상 주장: 어떤 IN·OPP·IDEA·HYP를 검증하는가
- 방향: support, contradict, mixed
- 직접성: direct, indirect, mixed
- 기준시점
- 표본·범위
- 원천 계열과 독립성
- 방법·한계

문제은행 안의 A·B 표시는 해당 외부 정본이 사용하는 자체 등급이며 이 문서의 등급으로 재사용하지 않습니다.

상태는 `active`, `qualified`, `reclassified`, `rejected`, `superseded`를 사용합니다. ID를 삭제하거나 다른 뜻으로 재사용하지 않습니다.

## 근거 사용 경계

- E-004는 어떤 문제를 먼저 검증할지 정하는 데 사용합니다. 개별 고객의 빈도·손실은 인터뷰로 다시 확인합니다.
- E-005는 좋은 아이디어의 형식과 해커톤 실행 제약에 사용합니다. 수상 확률이나 특정 아이디어의 시장성을 보장하지 않습니다.
- E-006은 솔루션이 정해진 뒤 구현·검증·복구 방식을 설계하는 데 사용합니다. 아이디어 점수를 높이는 고객 근거로 사용하지 않습니다.
- E-003은 과거 ID 보존용이며 근거가 아닙니다. HYP-001의 지지 근거로 계산하지 않습니다.
- HYP-001은 근거가 아니라 검증 대상입니다. HYP-001만으로 IDEA-001을 `validated` 또는 `selected`로 올릴 수 없습니다.
