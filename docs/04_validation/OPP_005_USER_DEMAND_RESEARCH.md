# OPP-005 사용자 규모·돌봄 수요·실제 행동·기능 우선순위 조사

## 1. 문서 목적

이 문서는 `돌봄 집현전 — 공식 돌봄 실행 라우터`의 핵심 가설을 검토하기 위해 다음 질문에 답합니다.

1. 예상 주요 사용자는 누구이며 몇 명인가?
2. 해당 사용자가 실제로 단시간 공식 돌봄을 필요로 하는가?
3. 어떤 상황에서 문제가 발생하고 기존 경로의 어디에서 막히는가?
4. 현재 확보한 자료에서 어떤 기능의 필요가 가장 반복되는가?
5. 정보·규칙 장벽과 실제 공급 부족 중 무엇이 더 큰가?
6. 실행 라우터가 기존 탐색보다 다음 행동을 빠르고 정확하게 만드는가?

공식자료, 공개 자기보고 행동사례, 제한형 지역 커뮤니티 참고사례와 미검증 가설을 분리합니다. 이용건수 같은 행정실적을 규모 판단의 1차 근거로 사용하고, 조회수·댓글·좋아요는 관심도 보조 신호로만 사용하며 발생률·시장규모·대표성으로 일반화하지 않습니다.

## 2. 현재 결론

### 2.1 현재 선정 방향

> 세종에서 6–36개월 영아를 가정양육하는 보호자에게 평일 2–4시간 돌봄 공백이 발생했을 때, 공식 제도와 기관정보를 바탕으로 가능한 돌봄 경로를 좁히고, 실제 가용성의 확인 상태를 구분해 예약·전화·상담 행동으로 연결한다.

다음 결과에 따라 고객, 문제, P0 범위 또는 아이디어를 수정할 수 있습니다.

- 보호자가 기존 아이사랑만으로 쉽게 해결하는 경우
- 문제의 핵심이 정보·판단이 아니라 절대적인 슬롯·인력 부족인 경우
- 공개데이터나 협력기관 정보로 신뢰할 수 있는 후보를 만들 수 없는 경우
- 공식 서비스로의 인계가 기존 방식보다 더 번거로운 경우
- 실시간·준실시간 가용성 없이 실행 라우터가 충분한 가치를 제공하지 못하는 경우

### 2.2 증거 수준

| 질문 | 현재 답 | 상태 |
|---|---|---|

| 어떤 기능 수요가 가장 강한가 | 실제 자리·매칭 확인, 공식 경로 비교, 신청규칙·다음 행동, 신뢰·적응 확인이 무순위 후보로 도출됐으나 상대 순위는 미확인 | 후보만 확인 |
| 라우터가 기존 방식보다 빠른가 | X-006 미실행 | 미확인 |

## 3. 예상 주요 사용자와 규모

### 3.1 제도상 대상

- 6–36개월 미만 영아
- 어린이집이나 유치원을 정규 이용하지 않는 가정양육 아동
- 평일 몇 시간 단위의 돌봄이 필요한 보호자
- 최신 공식 지원조건을 충족하고 아동등록·결제수단 등 이용 준비를 마친 가구

### 3.2 초기 사용자 가설

> 세종에서 6–18개월 영아를 주로 가정양육하며, 병원 진료·개인업무·보호자 피로·복직 준비·단시간 근로 등으로 평일 몇 시간의 비정형 돌봄 공백이 발생한 보호자

6–18개월은 초기 검증 표집을 위한 가설이며 세종 전체 보호자의 연령분포로 일반화하지 않습니다. 직업군도 확정하지 않고 최근 돌봄 공백의 상황과 행동을 기준으로 분류합니다.

### 3.3 현재 확인된 실제 이용

2025년 세종 시간제보육 만족도조사 결과보고에는 2025년도 시간제보육 이용자 총 431명과 만족도조사 응답자 61명(14.2%)이 기록돼 있습니다.

확인할 수 있는 것:

- 세종에서 공식 시간제보육 실제 이용이 존재함
- 현재 고객이 전적으로 상상에 기반한 것은 아님
- 성공 이용자층을 대상으로 초기 검증 가능

확인할 수 없는 것:

- 세종 전체 잠재사용자가 431명이라는 결론
- 431명이 중복을 제거한 아동·보호자·가구 중 어느 단위인지에 대한 확정
- 예약 실패자와 제도 미인지자까지 포함한 전체 수요
- 대규모 B2C 사업성

### 3.4 계수를 채운 잠정 규모 산식

규모는 `정책상 잠재대상`, `보고된 실이용자`, `이용건수`, `제품이 해결할 수 있는 핵심 사용자`를 서로 다른 단위로 나눕니다.

| 층위 | 계수와 산식 | 잠정 결과 | 근거·해석 경계 |
|---|---|---:|---|
| 6–35개월 아동 프록시 | 연 출생아 2,800명 × 30개월 ÷ 12개월 | 약 7,000명 | E-009의 보강값을 사용한 출생 규모가 30개월 동안 일정하고 전출입이 없다는 단순 코호트 가정. 세종 월령별 주민등록 원표로 교체 필요 |
| 가정양육 잠재대상 | 7,000명 × 39.3% | 약 2,750명, 반올림 약 2,800명 | 39.3%는 2024년 전국 0–2세 어린이집 미이용 비중(이용률 60.7%의 여집합)이다. 세종의 국공립 비율·신도시 인구구조·월령구성을 반영하지 않은 비례 적용 |
| 보고된 실이용자 | 세종 2025년 결과보고(E-011) | 431명 | 보고서가 `이용자 총 431명`으로 표기한다. 중복 제거 단위가 아동·보호자·가구 중 무엇인지는 미기재 |
| 조건부 침투 프록시 | 431명 ÷ 2,750명 | 약 15.7% | 분자·분모의 단위와 기준시점이 완전히 같다는 조건에서만 성립하며 실제 침투율로 확정하지 않음 |
| 조건부 격차 | 2,750명 − 431명 | 약 2,320명, 반올림 약 2,400명 | 제품 주소가능시장이나 미충족 수요가 아니라 원인 진단이 필요한 상한 성격의 풀 |
| 2024년 이용건수 | 전국 563,831건, 세종 10,048건 | 세종 비중 약 1.8% | E-024의 보육정책 DW시스템 행정실적. `건`은 사람 수·예약 실패·미충족 수요가 아님 |
| 반복이용 프록시 | 세종 10,048건 ÷ 보고된 이용자 431명 | 연 약 23.3건 | 2024년 건수와 2025년 이용자를 결합한 교차연도 조건부 계산이다. 실제 인당 평균으로 확정하지 않음 |

전국 이용건수에 세종 0–2세 인구비중 1.1%를 적용하면 `563,831건 × 1.1% = 약 6,200건`입니다. 그러나 같은 백서의 세종 행정실적은 10,048건으로 비례값보다 약 62% 큽니다. 따라서 전국 비례 외삽은 지역 원값이 없을 때의 비교선으로만 쓰고, 이 문서에서는 세종 실측 앵커를 우선합니다.

현재 근거로 방어할 수 있는 구조는 다음까지입니다.

> 잠재대상은 수천 명 규모의 시나리오이고, 공식 보고상 실이용자는 수백 명이며, 행정실적은 반복 이용과 양립한다.

2019년 공개사례의 주 1–2회 패턴은 반복 이용이 가능한지 보는 자릿수 점검에만 사용합니다. 오래된 단일 고빈도 이용자의 패턴으로 세종 평균을 검증하지 않습니다.

제품의 핵심 사용자 수에는 아직 다음 계수가 비어 있습니다.

```text
가정양육 잠재대상 약 2,800명
× 최근 3개월 내 평일 단시간 돌봄 공백 경험률
× 공식 돌봄 이용·탐색 의향률
× 기존 경로에서 정보·규칙·기관 선택 문제를 경험한 비율
= 핵심 사용자
```

약 2,400명의 조건부 격차가 정보 장벽 때문인지, `SLOT`·`TIME`·`DIST` 같은 공급 장벽 때문인지, 또는 공식 돌봄 필요가 없기 때문인지를 X-006에서 구분합니다.

아직 필요한 데이터:

- 세종 6–35개월 월령별 주민등록 인구와 어린이집 재원 아동
- 부모급여 현금·가정양육수당 수급 아동
- 시간제보육 이용자 431명의 중복 제거 단위
- 이용시간·재이용률
- 생활권·요일·시간대별 이용량
- 신청 실패·취소·대기·문의 건수
- 최근 단시간 돌봄 공백 경험률

### 3.5 정량·정성 방법의 역할 분리

- **정량 규모**: 전국·세종 행정실적은 표본 추정이 아니라 집계값으로 사용합니다. 다만 전국 값을 세종에 비례 적용하는 순간에는 지역구조 차이를 가진 모델 추정이 되므로 세종 원값으로 교차검증합니다.
- **정성 문제 구조**: 전국 공개사례는 문제 코드와 기능 후보를 만드는 귀추적 자료입니다. 사례 수로 세종의 발생률·우선순위·시장규모를 귀납 일반화하지 않습니다.
- **세종 검증**: X-006의 보호자 6명은 가설의 방향과 실패 원인을 확인하는 표집입니다. `하나만 제공한다면 선택할 기능` 문항으로 P0 우선순위를 정하되, 6명의 선택률을 세종 전체 선호율로 표현하지 않습니다.

## 5. 공식자료와 공개 관심 신호

### 5.1 행정실적과 공식 설문

교육부는 시간제보육을 병원 진료, 취업 준비, 단시간 근로 등으로 긴급하거나 일시적인 돌봄이 필요할 때 시간 단위로 이용하는 공식 보육서비스로 설명합니다.

| 자료 | 수치 | 확인되는 내용 | 해석 경계 |
|---|---:|---|---|
| 보육정책 DW시스템 2024년 이용실적(E-024) | 전국 563,831건·세종 10,048건 | 전국과 세종에서 실제 이용행동이 대규모로 집계됨 | `건`은 순이용자·잠재수요·예약 실패 수가 아님 |
| 공식 제공규모 | 2023년 1,000개 반·2025년 2,177개 반 | 제공 기반이 2년 사이 2배 이상 확대되어 오래된 예약 경험을 현행 규칙 근거로 쓰기 어려움 | 반 수 증가가 생활권·시간대별 슬롯 충분성을 뜻하지 않음 |
| 한국보육진흥원 2024년 만족도조사(E-025) | 이용부모 등 1,000명 대상·긍정 95.2% | 조사 응답자 다수가 서비스를 긍정 평가 | 전수 행정통계가 아닌 설문이며 표집·응답편향과 세종 차이를 별도 고려 |

이용건수와 지역 실적을 규모 판단의 1차 근거로 사용합니다. 95.2%는 이용 만족의 보조 근거이며 전수 실적이라고 표현하지 않습니다.

### 5.2 공개 관심 보조 신호

### 6.1 성공 이용과 보호자 회복(E-016)

블라인드 「시간제보육 너무 좋다」에서는 육아휴직 중인 보호자가 6개월 아동을 주 1–2회, 회당 2–3시간 맡기고 휴식·개인업무·독서·공부에 활용했습니다. 재충전 이후 아이와 더 잘 놀아주고 짜증이 줄었다고 설명했습니다.

### 6.3 2025년 공식 센터 게시 이용자 답변(E-026)

- 2025년 4월 7일 공식 센터 게시물로 E-016보다 현행성이 높음

직접 관련 사례에서 확인된 패턴:

- 보호자 휴식과 어린이집 적응을 위한 시간제보육 이용
- 원하는 시간 조기마감과 다른 생활권 이동
- 세종 8개월 아동 보호자의 시설환경·교사·적응방식·방문형 대안 질문

- 정부지원 아이돌봄의 반복·장기 이용
- 첫째 등원과 9개월 둘째 가정양육 병행 중 체력·가사 부담

정규 어린이집 탐색사례는 시간제보육 수요의 직접근거가 아니라 거리, 대기, 월령, 운영시간, 비용, 교사 근속, 시설환경, 적응 방법과 이용후기 등 실행카드 질문필드 설계에만 사용합니다.

## 9. 통합 문제 구조

```text
병원·출장·복직·단시간 업무·보호자 피로
→ 짧은 돌봄 필요 발생
→ 가족·지인·시간제보육·방문형 아이돌봄·연장보육 탐색
→ 자격·예약시각·최소시간·대기·비용·거리 판단
→ 시설·교사·돌보미·아동 적응에 대한 신뢰 확인
→ 예약 또는 매칭 시도
→ 예약 마감·미매칭·문의처 혼란
→ 가족 도움·일정 변경·휴가·퇴사 등 대안 선택
```

| 코드 | 의미 |
|---|---|
| INFO | 필요한 정보·후기·확인항목을 찾지 못함 |
| RULE | 자격·반 유형·예약기한·최소시간을 오해 |
| ROUTE | 어떤 서비스·기관·채널을 선택할지 모름 |
| SLOT | 적합 기관 또는 방문 돌보미의 실제 가용성이 없음 |
| TIME | 운영시간이 맞지 않거나 결정 마감이 촉박함 |
| DIST | 접근 가능한 기관이 없음 |
| TRUST | 낯선 시설·교사·돌보미·적응에 대한 우려 |
| SETUP | 아동등록·카드·서류·적응 준비 문제 |
| ALT | 가족·조부모·연장보육·일정 변경 등 다른 대안 선택 |
| HANDOFF | 아이사랑·복지로·기관·행정복지센터로 이동하는 과정이 번거로움 |

`COST`와 `WORK_LOSS`는 문제 코드가 아니라 비용·일정·직장 손실 필드로 기록합니다. `SUPPLY`는 `SLOT`, `TIME`, `DIST`와 중복돼 별도 코드로 만들지 않습니다.

## 10. 기능 후보 가설(E-022)

공식 개선자료와 공개·제한형 사례에서 반복된 문제를 기능 후보로 바꿨습니다. 사례 수가 적고 편의표본이므로 현재 단계에서는 후보 사이의 순서를 정하지 않습니다.

> 사용자가 가장 직접적으로 원하는 결과는 내 아이의 월령·필요시간·생활권을 기준으로 실제로 맡길 가능성이 있는 공식 경로를 찾고, 지금 확인해야 할 자리·매칭 상태와 다음 행동을 아는 것입니다.

| 기능 후보(무순위) | 현재 근거 | X-006에서 확인할 질문 |
|---|---|---|
| 실제 슬롯·매칭 상태 또는 정확한 확인경로 표시 | 예약 조기마감, 제한 인원, 8회 미매칭, 배정 대기 사례 | 하나만 제공할 때 이 기능을 고르는가, 상태정보가 없으면 가치가 사라지는가 |
| 상황별 공식 돌봄 경로 비교·판정 | 시간제보육·방문형 아이돌봄·연장보육·가족돌봄 비교 반복 | 보호자가 실제 사건에서 경로 선택을 잘못했거나 되돌아갔는가 |
| 신청규칙·준비사항·다음 행동 안내 | 예약 개시시각, 최소시간, 등록·카드, 문의기관 혼란 | 규칙 설명이 첫 실행 가능한 행동까지 시간을 줄이는가 |
| 기관 신뢰·아동 적응 확인 체크리스트 | 교사·환경·돌보미·분리·적응 불안 반복 | 신뢰·적응 정보가 실제 예약 또는 문의 결정에 필요한가 |
| 거리·이동 가능성 기반 후보 축소 | 다른 생활권 이동, 가까운 기관 부족 사례 | 생활권 필터가 후보를 유의미하게 줄이는가, 아니면 공급 부족만 드러내는가 |

순위는 X-006의 `하나만 제공할 경우 선택할 기능과 이유` 응답과 과업 성과를 함께 본 뒤 P0 범위에 한해 확정합니다.

### 10.1 구현 가능한 P0와 사용자 욕구의 차이

가장 강한 욕구는 실제 슬롯·매칭 확인이지만 외부에서 사용할 수 있는 실시간 시간제보육 슬롯 API는 확인되지 않았습니다. 따라서 P0에서 확인되지 않은 상태를 `예약 가능` 또는 `자리 있음`으로 표시하지 않습니다.

현재 구현 가능한 P0:

1. 자녀 월령·가정양육 여부·필요시간·생활권 입력
2. 시간제보육·방문형 아이돌봄 등 제도상 가능한 경로 판정
3. 공개정보상 후보 기관 축소
4. `기관 직접 확인`, `아이사랑 확인 필요`, `전화 확인 필요`, `마감 확인`, `확인 불가` 상태 구분
5. 아동등록·카드·서류·적응·문의 질문 체크리스트
6. 아이사랑·복지로·기관전화 등 공식 다음 행동으로 인계
7. 공식 경로가 없을 때 대안과 미충족 상태 기록

핵심 기능 문장:

> 아이 월령, 필요한 날짜·시간과 생활권을 입력하면 시간제보육·방문형 아이돌봄 등 가능한 공식 경로를 판정하고, 실제 가용성의 확인 상태를 구분해 지금 해야 할 예약·전화·준비 행동까지 하나의 실행카드로 제공한다.

## 11. 서비스 범위와 안전 경계

입력:

- 자녀 월령
- 가정양육 여부
- 필요한 날짜와 시간
- 현재 시각
- 대략적 생활권과 이동 범위
- 차량 여부
- 아이사랑 아동등록 여부
- 국민행복카드 준비 여부

수집하지 않는 정보:

- 아동 이름·주민등록번호·정확한 생년월일
- 상세주소·건강정보
- 카드번호·아이사랑 계정정보

판정은 버전이 붙은 규칙표와 코드로 처리하며 AI는 질문 보완과 설명에만 사용합니다. 실시간 슬롯 데이터가 없을 때 `예약 가능`, `자리 있음`, `예약 성공`이라고 단정하지 않습니다.

### 12.2 기존 방식과 시안 과업 비교

공통 과업 예시:

> 14개월 자녀를 내일 오전 10시부터 오후 1시까지 맡겨야 한다. 세종 동지역 거주, 차량 없음, 아동등록 여부 불확실. 이용 가능한 공식 돌봄 경로와 다음 행동을 찾으시오.

측정:

- 첫 실행 가능한 행동까지 시간
- 방문 페이지·전화 수
- 잘못 선택한 서비스·기관 수와 되돌아간 횟수
- 제도상 가능과 실제 예약상태 구분 여부
- 최종 행동 설명 정확도

### 12.3 기관 데이터 대조

시간제보육 관련 기관 10곳의 공개정보와 전화 확인 결과를 비교합니다.

- 운영 여부·반 유형·수용 월령·운영시간
- 당일 접수·준비물·실제 슬롯 확인방법
- 반복 문의와 기관이 갱신 가능한 최소 상태
- 공개정보 기준일

## 13. Go / Pivot / Stop

### GO

- 보호자 6명 중 4명 이상이 최근 실제 사건을 구체적으로 재구성
- 3명 이상이 둘 이상의 검색·문의 경로를 사용
- 3명 이상에게 `INFO`, `RULE`, `ROUTE`, `SETUP` 문제가 확인
- 기존 방식에서 4명 이상이 5분 안에 정확한 다음 행동을 찾지 못함
- 시안 사용 시 4명 이상이 5분 안에 다음 행동과 미확인 사항을 구분
- 첫 실행 가능한 행동까지 시간이 30% 이상 감소
- 공식 사례 10건에서 치명적 오안내 0건

### PIVOT

- 6명 중 4명 이상에게 `SLOT`, `TIME`, `DIST`가 핵심 원인
- 부모는 경로를 쉽게 찾지만 실제 공급이 없음
- 슬롯·매칭 상태가 없는 실행카드는 충분한 가치가 없음
- 기관이 최소 상태정보를 제공할 의향이 있음

전환 후보: `부모용 실행 라우터 + 생활권·월령·시간대별 미충족 돌봄 수요 대시보드`

### STOP

- 대부분 아이사랑만으로 3–5분 안에 정확히 해결
- 공개정보로 후보를 신뢰성 있게 좁힐 수 없음
- 기관 협력 없이는 핵심 가치가 성립하지 않음
- 보호자가 공식 돌봄을 실제 대안으로 고려하지 않음
- 공식 시스템으로 인계하는 과정이 기존보다 복잡함
- 민감한 아동정보 없이 가치를 제공할 수 없음

## 14. 현재 한계와 판정

현재 자료는 단시간 공식 돌봄 수요의 존재, 전국·세종 이용건수의 규모, 대표 촉발 상황, 예약·매칭·규칙·신뢰 문제와 무순위 기능 후보를 부분적으로 지지합니다. 잠정 산식은 `잠재 수천 명, 보고된 실이용자 수백 명, 반복 이용과 양립하는 행정실적` 구조를 보여줍니다. 그러나 다음은 확인되지 않았습니다.

- 세종 월령·재원 원표로 계산한 정확한 정책상 잠재대상과 제품 핵심 사용자 규모
- 2024년 이용건수와 2025년 이용자 수의 단위·대상 일치 여부
- 세종 보호자의 사건 발생 빈도와 평균 손실
- 기능별 실제 선택·반복사용 의향과 P0 우선순위
- 정보 장벽과 공급 장벽의 상대적 비중
- 아이사랑 단독 대비 라우터의 완료시간·오류 개선
- 실시간 가용성 없이 제공할 수 있는 가치

따라서 이번 조사로 `OPP-005`, `IDEA-002`, `SOL-002`의 Gate 상태를 변경하지 않습니다. X-006과 기관 데이터 스파이크가 완료될 때까지 기존 `waived` 상태를 유지합니다.
