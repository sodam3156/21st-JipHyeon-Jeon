# 제품 요구사항 문서

## 목표

모임 제안자가 여러 참여자의 제약을 정리하고, 실행 가능한 대안 3개를 비교해 최종안을 선택하는 과정을 하나의 데모 흐름으로 보여줍니다.

## 성공 지표

- 데모 사용자가 별도 설명 없이 입력 → 비교 → 우선순위 변경 → 확정을 완료합니다.
- 모든 추천안에 시간, 예상 비용, 이동 부담, 선호 충족 근거가 표시됩니다.
- 존재하지 않는 장소나 확인되지 않은 영업·교통 정보를 사실처럼 제시하지 않습니다.
- 입력부터 최종 카드까지 데모 환경에서 3분 이내 완료합니다.

## 사용자 스토리와 수용 기준

### US-01 모임 조건 입력

모임 제안자로서 목적, 인원, 시간, 예산, 출발지, 필수·회피 조건을 입력하고 싶다.

- 필수 항목이 비면 다음 단계로 진행되지 않는다.
- 자연어 입력은 구조화된 조건으로 확인할 수 있다.
- 사용자가 AI 해석을 수정할 수 있다.

### US-02 충돌 조건 확인

모임 제안자로서 모두의 조건 중 동시에 만족할 수 없는 부분을 알고 싶다.

- 충돌한 참여자와 조건이 표시된다.
- 시스템은 임의로 조건을 버리지 않는다.
- 완화 가능한 조건을 사용자에게 질문한다.

### US-03 대안 비교

모임 제안자로서 실행 가능한 3개 안을 같은 기준으로 비교하고 싶다.

- 각 안에 일정, 장소, 이동, 비용, 충족·미충족 조건이 표시된다.
- 추천 근거가 데이터와 입력 조건을 연결해 설명된다.
- 데모 데이터는 실제 데이터와 구분된다.

### US-04 우선순위 조정

모임 제안자로서 비용, 이동, 취향 중 중요한 기준을 바꾸고 싶다.

- 가중치 변경 후 순위와 설명이 함께 바뀐다.
- 이전 값으로 되돌릴 수 있다.
- 변경 이유가 한 문장으로 표시된다.

### US-05 최종안 확정

모임 제안자로서 선택한 안을 참여자에게 공유하고 싶다.

- 최종 카드에 일시, 장소, 비용, 이동 요약이 포함된다.
- 복사 또는 이미지 저장 가능한 형태를 제공한다.
- 확정 전 미충족 조건을 다시 보여준다.

## 비기능 요구사항

- 모바일 화면을 우선합니다.
- 데모 중 API 실패 시 준비된 검증 데이터로 복구할 수 있습니다.
- 개인 식별 정보는 최소한으로 수집합니다.
- 응답 대기 중 현재 처리 단계가 보입니다.
- AI 출력은 구조화된 형식으로 검증한 뒤 화면에 표시합니다.

## 미정 기술 항목

- 장소 데이터 원천과 허용 범위
- 대중교통 정보의 실시간 여부
- LLM 제공자와 비용 상한
- 참여자 링크 응답을 P0에 포함할지 여부
- 서버 저장 없이 데모 가능한 범위
